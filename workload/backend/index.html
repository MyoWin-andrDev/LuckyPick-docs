    Backend Developer Workload

    Developer: Myo

    Server-side work required to support the LuckyPick EuroMillions app.

    Summary

    Category Deliverables
    Database 6 tables, indexes, migrations
    REST API ~20 LuckyPick-specific endpoints
    Data Scraper Automated cron (Tue + Fri)
    Push Service FCM + APNs dispatch
    IAP Validation StoreKit 2 + Play Billing v6 receipt check
    Admin Panel Internal dashboard
    Infrastructure PostgreSQL, Redis, cron, server

    1. Database Design & Setup

    PostgreSQL Tables

    draws — official EuroMillions draw results

    draws (
  id            BIGSERIAL PRIMARY KEY,
  draw_date     DATE NOT NULL UNIQUE,
  draw_number   INT,
  numbers       INT[5] NOT NULL,           -- sorted, 1–50
  lucky_stars   INT[2] NOT NULL,           -- sorted, 1–12
  jackpot_eur   BIGINT,                    -- null until prize data available
  ingested_at   TIMESTAMPTZ DEFAULT now(),
  source_url    TEXT
)

    prize_tiers — prize breakdown per draw

    prize_tiers (
  id          BIGSERIAL PRIMARY KEY,
  draw_id     BIGINT REFERENCES draws(id),
  tier        SMALLINT NOT NULL,           -- 1 (jackpot) to 13
  match_desc  TEXT NOT NULL,              -- "5 + 2 Stars", "3 + 1 Star", etc.
  winners     INT,
  prize_eur   BIGINT
)

    statistics — rolling frequency cache (rebuilt after each draw ingestion)

    statistics (
  id              BIGSERIAL PRIMARY KEY,
  stat_type       TEXT NOT NULL,           -- 'main' | 'star'
  number          SMALLINT NOT NULL,
  frequency_100   SMALLINT NOT NULL,       -- count in last 100 draws
  frequency_20    SMALLINT NOT NULL,       -- count in last 20 draws
  trend_score     FLOAT,                   -- (freq_20/20) / (freq_100/100)
  updated_at      TIMESTAMPTZ DEFAULT now(),
  UNIQUE(stat_type, number)
)

    users — registered app users

    users (
  id              BIGSERIAL PRIMARY KEY,
  device_id       TEXT UNIQUE NOT NULL,    -- anonymous device token
  fcm_token       TEXT,
  apns_token      TEXT,
  locale          VARCHAR(5) DEFAULT 'en',
  timezone        TEXT,
  created_at      TIMESTAMPTZ DEFAULT now(),
  last_active_at  TIMESTAMPTZ
)

    subscriptions — IAP state per user

    subscriptions (
  id                  BIGSERIAL PRIMARY KEY,
  user_id             BIGINT REFERENCES users(id),
  platform            TEXT NOT NULL,         -- 'ios' | 'android'
  product_id          TEXT NOT NULL,         -- 'monthly' | 'yearly' | 'lifetime'
  original_txn_id     TEXT UNIQUE NOT NULL,
  purchase_date       TIMESTAMPTZ,
  expires_date        TIMESTAMPTZ,           -- null for lifetime
  is_active           BOOLEAN DEFAULT true,
  raw_receipt         JSONB,
  updated_at          TIMESTAMPTZ DEFAULT now()
)

    scraper_runs — audit log for the automated scraper

    scraper_runs (
  id          BIGSERIAL PRIMARY KEY,
  run_at      TIMESTAMPTZ DEFAULT now(),
  status      TEXT NOT NULL,               -- 'success' | 'failed' | 'no_new_draw'
  draw_date   DATE,                        -- null if no draw found
  error_msg   TEXT,
  duration_ms INT
)

    Indexes

    CREATE INDEX draws_draw_date_idx ON draws(draw_date DESC);
CREATE INDEX prize_tiers_draw_id_idx ON prize_tiers(draw_id);
CREATE INDEX statistics_type_number_idx ON statistics(stat_type, number);
CREATE INDEX subscriptions_user_id_idx ON subscriptions(user_id);
CREATE INDEX subscriptions_original_txn_idx ON subscriptions(original_txn_id);

    Redis Keys (Cache & Rate Limiting)

    Key Pattern TTL Purpose
    draw:latest Until next draw Latest draw JSON
    statistics:main Until next draw Main number frequency array
    statistics:stars Until next draw Lucky Star frequency array
    user:{id}:free_picks Until midnight (user TZ) Daily free pick counter
    push:queue:{draw_date} 24h Push batch job deduplication

    2. REST API Endpoints

    All endpoints are prefixed /api/v1. Auth-required endpoints validate Authorization: Bearer <token>.

    Public (no auth)

    Method Path Description
    GET /public/draws/latest Latest EuroMillions draw + prize breakdown
    GET /public/draws Draw history list (paginated, last 100)
    GET /public/draws/{id} Draw detail + full prize breakdown
    GET /public/statistics Number and Lucky Star frequency data
    POST /public/auth/register Anonymous device registration, returns JWT
    POST /public/auth/refresh Token refresh

    Authenticated (/usr/*)

    Method Path Description
    GET /usr/me Current user profile + subscription status
    PUT /usr/me/tokens Update FCM / APNs push token
    GET /usr/me/free-picks Today's remaining free pick count
    POST /usr/me/free-picks/consume Decrement free pick counter (1 of 3)
    GET /usr/picks Active pick set (combinations list)
    POST /usr/picks/combinations Add combination to active set
    DELETE /usr/picks/combinations/{id} Remove combination
    POST /usr/picks/sets Archive active set, start new set
    GET /usr/picks/sets All archived sets
    GET /usr/notification-setting Current notification preferences
    PUT /usr/notification-setting Update notification toggles
    POST /usr/iap/validate/ios Validate StoreKit 2 JWS transaction
    POST /usr/iap/validate/android Validate Play Billing purchase token
    POST /usr/iap/restore Re-check all prior purchases for user

    Webhook

    Method Path Description
    POST /webhook/apple/notifications Apple Server Notifications (renewal, expiry, refund)
    POST /webhook/google/notifications Google Play Real-Time Developer Notifications

    3. Automated Draw Scraper

    Runs on a cron — Tuesday and Friday at 20:45 CET (shortly after draw close, results typically published 21:00–21:30 CET).

    Cron schedule: 

    45 20 * * 2,5   /usr/local/bin/luckypick-scraper

    Scraper logic:

    1. Fetch official results from Belgian National Lottery or EuroMillions API
2. Parse draw date, 5 main numbers, 2 Lucky Stars
3. Check draws table — skip if draw_date already exists
4. INSERT draw record (numbers + lucky_stars; jackpot_eur may be null initially)
5. Attempt to fetch prize tier data; INSERT prize_tiers if available
6. Rebuild statistics table:
     a. Pull last 100 draw dates
     b. Count frequency of each number (1–50) and star (1–12)
     c. Count frequency in last 20 draws
     d. Compute trend_score per number
     e. UPSERT statistics rows
7. Invalidate Redis keys: draw:latest, statistics:main, statistics:stars
8. Dispatch push notifications (see §4)
9. Log result to scraper_runs

    Error handling:

    • Retry up to 3 times with 5-minute backoff if HTTP fetch fails
    • If prize data unavailable after 3 retries, store draw without prizes; a second cron at 00:00 CET re-attempts prize fetch only
    • Alert (email / Slack) on 3 consecutive scraper_runs.status = 'failed'

    4. Push Notification Service

    Triggered by the scraper after a successful draw ingestion.

    Notification Types

    results_available (every draw, Tue/Fri ~21:00 CET) 

    {
  "title": "EuroMillions Results Are In!",
  "body": "Tap to see the winning numbers.",
  "data": { "type": "results_available", "draw_id": 1234 }
}

    draw_reminder (Tue/Fri at 18:00 CET — 2h before draw close) 

    {
  "title": "EuroMillions Draw Tonight",
  "body": "Have your lucky numbers ready.",
  "data": { "type": "draw_reminder" }
}

    jackpot_won (only when Tier 1 has ≥1 winner) 

    {
  "title": "Someone Won the Jackpot!",
  "body": "See the results and winners.",
  "data": { "type": "jackpot_won", "draw_id": 1234 }
}

    Dispatch Logic

    For each notification type that fires:
  1. Query users WHERE notification_setting_{type} = true
  2. Split by platform (ios / android)
  3. iOS: FCM HTTP v1 → APNs gateway  OR  APNs direct
  4. Android: FCM HTTP v1 → Firebase → device
  5. Handle invalid token responses → remove stale tokens from users table
  6. Log batch result (sent / failed / invalid token)

    Batch size: send in batches of 500 tokens per FCM request to stay within rate limits.

    5. IAP Receipt Validation

    iOS — StoreKit 2 (JWS)

    POST /usr/iap/validate/ios
Body: { "transaction_jws": "<signed_transaction>" }

1. Decode JWS header → fetch Apple root certificate
2. Verify signature chain
3. Extract productId, originalTransactionId, purchaseDate, expiresDate
4. UPSERT subscriptions row
5. Update user subscription status
6. Return: { "is_premium": true, "expires_at": "..." }

    Apple Server Notifications webhook handles renewals, cancellations, refunds automatically.

    Android — Google Play Billing v6

    POST /usr/iap/validate/android
Body: { "purchase_token": "...", "product_id": "..." }

1. Call Google Play Developer API:
   GET purchases.subscriptions.get or purchases.products.get
2. Verify purchaseState = 0 (Purchased)
3. UPSERT subscriptions row
4. Return: { "is_premium": true, "expires_at": "..." }

    Google Play Real-Time Developer Notifications (Pub/Sub webhook) handles renewals and cancellations.

    6. Admin Panel (Internal)

    Lightweight internal dashboard — not user-facing.

    Feature Description
    Draw history table All draws, editable jackpot / prize data manually if scraper misses
    Manual draw import CSV or form to insert a draw if scraper fails
    Scraper run log Status, duration, error messages per run
    User count Total registered, active (last 30 days), premium
    Push log Sent / failed / invalid token counts per notification batch
    Subscription lookup Search by original_txn_id or user_id
    Statistics preview Current hot / cold / trending numbers visualised

    Item Choice

    Database PostgreSQL 15+ (managed or self-hosted)
    Cache Redis 7+
    Language / Framework Developer's choice — Go, Node.js, or Python (FastAPI) recommended for async performance
    HTTPS Let's Encrypt / Caddy automatic TLS
    Cron System cron or cron-in-app scheduler
    Logging Structured JSON logs (stdout), rotated or shipped to log aggregator
    Monitoring Uptime check on /health endpoint; alert on scraper failure

    8. Security Checklist

    • All /usr/* routes validate JWT expiry and signature before processing
    • IAP validation always calls Apple / Google — never trust client-side receipts alone
    • Rate limit free pick consumption endpoint (max 3 per user per day, enforced server-side)
    • Rate limit auth endpoints (register / refresh) to prevent token farming
    • Scraper source URL is hardcoded — not user-supplied (no SSRF surface)
    • Admin panel is IP-restricted or behind VPN — not publicly routable
    • Push tokens stored encrypted at rest
    • pg_dump backups tested monthly for restore integrity
