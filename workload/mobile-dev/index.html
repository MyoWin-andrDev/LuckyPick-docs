    Mobile Developer Workload

    Flutter app (iOS + Android) — Myo and Zaw.

    Developer Focus
    Myo Architecture, push, l10n, IAP, generation engine, CI/CD
    Zaw UI screens, standard API integration, UX flows

    Myo

    Project Foundation & Architecture

    • Project setup: Flutter, folder structure, pubspec.yaml dependencies
    • Riverpod architecture: ProviderScope, provider families, StateNotifierProvider pattern
    • GoRouter setup: StatefulShellRoute (5 tabs), auth redirect guard, push / go navigation
    • Dio HTTP client: dioClientProvider, Authorization: Bearer interceptor, 401 token refresh queue, X-Timezone header
    • json_helpers.dart: parseInt, parseString, parseBool, parseDouble, parseGlobalDateTime
    • _safe<T>(call, fallback) wrapper for optional/unimplemented endpoints
    • PagedResponse<T> model and pagination utilities
    • App theme: AppColors, AppTypography, dark / light theme setup, Aurora gradient tokens
    • Flavors / dart-define: API_BASE_URL injection for dev / staging / production

    Localization (l10n)

    • l10n.yaml configuration (synthetic-package: false, app_ko.arb template)
    • All 7 ARB files: ko (template), en, ja, zh, th, ru, hi
    • Every user-visible string keyed — never hardcoded
    • flutter gen-l10n pipeline, AppL10n.of(context) alias t
    • Language auto-detection on first launch
    • In-app language switch (Settings screen → triggers locale rebuild)

    Push Notifications (FCM + APNs)

    • Firebase project setup, google-services.json / GoogleService-Info.plist
    • FCM token registration and sync to backend on login / token refresh
    • APNs entitlements, provisioning profiles (iOS)
    • firebase_messaging package integration
    • Foreground / background / terminated message handling
    • Notification tap routing (deep link to Results or My Picks screen)
    • Notification type handling:
    • draw_reminder — fires before each Tuesday / Friday draw
    • results_available — fires after official numbers are published
    • jackpot_won — prize-tier win notification
    • Permission request flow: pre-prompt dialog → OS permission dialog → graceful decline handling

    In-App Purchase (IAP)

    • iOS: StoreKit 2 (storekit_2 / in_app_purchase package)
    • Product fetching for 3 SKUs: monthly, yearly, lifetime
    • Purchase flow, transaction listener, JWS receipt validation via backend
    • Subscription status check on app launch and foreground
    • Restore purchases
    • Android: Google Play Billing v6+
    • BillingClient setup, product details query
    • Purchase flow, PurchaseHistoryRecord processing
    • Backend server-side token validation
    • Restore purchases
    • Free tier enforcement: daily counter (3 free picks), reset at midnight user-local time
    • Premium gate checks across all 10 Lucky Modes and Statistics screen
    • SubscriptionState notifier: Free / Premium / Expired — drives all gating UI

    Generation Engine (Client-Side)

    • Birthday Mode: DOB → numerological seed → weighted number selection
    • Horoscope Mode: day + month → zodiac sign → zodiac seed → weighted selection
    • Pet Mode: pet name hash + animal-type factor → seed
    • Family Mode: aggregate of member seeds → combined generation
    • Lucky Color Mode: selected colour index → colour-seed offset → weighted selection
    • Lucky Number Mode: user numbers anchored, remaining filled with weighted random
    • Hot / Cold / Trending / Smart Mix: pulls DrawStatistics from API → applies frequency weights
    • All modes: output exactly 5 unique main numbers (1–50) + 2 unique Lucky Stars (1–12)
    • Generation is client-side — no API call needed after statistics are fetched

    Firebase & Remote Config (if used)

    • Firebase Analytics event tracking: generate_numbers, mode_selected, premium_purchase, share
    • Crashlytics integration
    • Remote Config for feature flags (if applicable)

    CI/CD & Distribution

    • Xcode project signing: team ID, bundle ID, provisioning profiles, entitlements
    • Android keystore signing config (release build)
    • flutter build ios --release / flutter build apk --release / flutter build appbundle
    • App Store Connect upload (Transporter or xcrun altool / fastlane)
    • Google Play Console upload
    • TestFlight / internal test track distribution

    Zaw

    Screens to Implement

    All screens follow the Figma / design handoff. Zaw implements the layouts and wires the standard API calls. Myo handles any screen that requires IAP gating logic or push permission flows.

    Splash & Welcome

    • SplashScreen — 1-second hold, then navigate to Welcome or Home (if already authenticated)
    • WelcomeScreen — logo, GET STARTED button, legal disclaimer text

    Home

    • HomeScreen — pick counter, Lucky Modes preview carousel, Discover Premium section
    • GeneratedNumbersScreen — result display with 5 balls + 2 stars, Save / Generate Again / Share actions
    • Free limit reached state (inline on HomeScreen)

    Lucky Modes

    • LuckyModesScreen — grid/list of all 10 modes + Quick Pick, PREMIUM label on locked modes
    • Mode input screens (one each):
    • BirthdayModeScreen
    • HoroscopeModeScreen (zodiac auto-display)
    • PetModeScreen (7 animal type pills)
    • FamilyModeScreen (+ADD MEMBER, relationship selector, EDIT / START NEW FAMILY)
    • LuckyColorModeScreen (10 colour circles, SURPRISE ME)
    • LuckyNumberModeScreen (1–3 number chips, validation)
    • Hot, Cold, Trending, Smart Mix — shared simple layout with GENERATE button
    • ModeResultScreen — shared result screen with mode badge and action row

    My Picks

    • MyPicksScreen — active set, combination list, ••• menu (Replace / Remove / Share), START NEW SET
    • SavedSetsScreen — archived sets list, expand to view combinations
    • Empty My Picks state, Set Complete (12/12) state

    Results & Draw History

    • ResultsScreen — latest draw, 5+2 balls, PRIZE BREAKDOWN section, pending states
    • DrawHistoryScreen — scrollable list of last 100 draws
    • DrawDetailScreen — draw-specific result + prize breakdown

    Statistics

    • StatisticsScreen — Hot / Cold / Trending tabs, number frequency bar, Lucky Star frequency
    • Free user limited preview (top 5 only), Premium full view
    • Disclaimer label always visible

    Notifications Settings

    • NotificationsSettingsScreen — three toggles (Draw Reminders, Results Available, Jackpot Won)

    Social Sharing

    • ShareHelper utility — generates sharing card image, triggers native share sheet
    • Post-share state: remain on current result screen, no navigation

    Settings / More

    • SettingsScreen — full menu list (Premium, Draw History, Notifications, Language, Support, Rate, Website, Restore, About, Privacy, T&C)
    • AboutScreen — version, tagline, legal links

    Premium Screen

    • PremiumScreen — benefits list, three plan cards (Monthly / Yearly / Lifetime), ✕ back button, RESTORE PURCHASES link
    • Post-purchase confirmation overlay / screen

    API Integration (Standard Endpoints)

    Zaw wires these API calls using XxxApi(ref.read(dioClientProvider).dio):

    Endpoint Group Screens
    GET /usr/home HomeScreen pick counter, latest draw preview
    GET /public/store Lucky Modes browser (if mode metadata is server-driven)
    GET /usr/me Profile / subscription status (used by SubscriptionState — read only)
    GET /public/instant-call/draws/latest ResultsScreen
    GET /public/instant-call/draws DrawHistoryScreen
    GET /public/instant-call/draws/{id} DrawDetailScreen
    GET /usr/mypage My Picks active set and saved sets
    POST /usr/mypage/combinations Save combination to My Picks
    DELETE /usr/mypage/combinations/{id} Remove combination
    POST /usr/mypage/sets Start New Set
    GET /usr/notification-setting NotificationsSettingsScreen load
    PUT /usr/notification-setting Toggle save

    State Management (Screens Zaw Owns)

    • StateNotifierProvider per screen for list/paged data
    • StateProvider<bool> for simple toggles (notification switches)
    • ref.watch / ref.read usage following project convention
    • Loading, error, and empty states on every provider-backed screen
